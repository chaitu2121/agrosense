> Built from the farmlands, for the farmlands. A precise, zero-latency agricultural logic engine.

Most AgriTech platforms are designed in corporate offices using rough estimates and generic advice. I live in a rural village in Maharashtra, India, and I saw firsthand that farmers need actual, computationally verified science to avoid losing money and ruining their soil.

## 🏗️ What is AgroSense AI?
AgroSense AI is a lightweight, mobile-first ecosystem divided into two parts: a **Mathematical Logic Engine** (Frontend) and a **Neural Assistant** (Backend AI). 

Instead of overwhelming the user, the UI is built with a custom glassmorphism design that feels like a native app, running at 60fps even on low-end rural 3G networks.

### The Core Instruments:
* 📊 **Deterministic Risk Predictor:** Before a seed is planted, this matrix cross-examines soil integrity, seasonal constraints, and water sources to output a definitive success probability.
* 🧮 **Precision Chemistry:** It doesn't just guess NPK values. It dynamically calculates exact 50kg bags of Urea, DAP, and MOP required. It even algorithmically deducts the 18% Nitrogen overlap naturally found in DAP to ensure **zero chemical waste**.
* 💧 **FAO-Standard Hydration:** Hardcoded with the UN FAO Penman-Monteith methodology, it cross-references crop evapotranspiration coefficients against acreage to output exact volumetric water limits.
* 🧠 **FarmCulture AI:** Powered by `Llama-3.1-8B-Instruct`, this is the brain of the app. I bypassed standard templates to inject a custom CSS payload, making the AI interface seamlessly match the dark, cinematic aesthetic of the main dashboard.

## ⚙️ Engineering on a Smartphone (The CI/CD Story)
If you look at the commit history, you will see over **90+ production deployments** for the V3.0 stable release. 

Why so many? Because when you code an entire application on a mobile screen, you do not have the luxury of a `localhost` environment. I had to test in production. 

Every micro-adjustment to the DOM and every complex stoichiometric calculation required a full GitHub Pages deployment just to verify the render. Pushing code this way forced me to develop an uncompromising standard of CI/CD discipline, memory management, and code optimization.

### Tech Stack
* **Frontend:** HTML5, CSS3 (Custom Glassmorphism & Viewport Snapping), Vanilla JavaScript
* **Backend / AI Bridge:** Python, Gradio (Custom CSS DOM Hijack)
* **LLM:** `meta-llama/Llama-3.1-8B-Instruct` (via Hugging Face)
* **Deployment:** GitHub Pages & Hugging Face Spaces
